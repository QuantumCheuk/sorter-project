## 1. 安全警告

### ⚠️ 電氣安全

| 危險等級 | 說明 |
|---------|------|
| 🔴 高危 | 嚴禁在 Pi 開機狀態下觸摸 GPIO 針腳（3.3V/5V 可能損壞 Pi） |
| 🔴 高危 | 嚴禁在通電狀態下拔插 I2C/SPI 設備（先斷電再操作） |
| 🟡 中危 | 12V 電源適配器表面可能發熱，確保散熱通風 |
| 🟡 中危 | 空壓機運行時嚴禁打開壓縮空氣管路（0.5-1bar仍有壓力） |

### ⚠️ 機械安全

| 危險等級 | 說明 |
|---------|------|
| 🔴 高危 | 設備運行時嚴禁將手指伸入振動給料器 bowl 內部 |
| 🔴 高危 | 馬達與傳動機構運轉時嚴禁進行任何調整或清潔 |
| 🟡 中危 | 尺寸分選孔板更換後務必確認固定螺絲已鎖緊 |
| 🟡 中危 | 3D 列印件磨損或裂紋時立即停機更換（PLA 疲勞斷裂風險） |

### ⚠️ 咖啡豆處理安全

| 危險等級 | 說明 |
|---------|------|
| 🟢 低危 | 處理發霉或變質豆時建議佩戴 N95 口罩（孢子吸入風險） |
| 🟢 低危 | 操作含水率檢測時避免長時間接觸樣本（微量輻射假象） |
| 🟡 中危 | 剔除的缺陷豆建議密封丟棄，避免污染環境 |

### 🔒 一般規定

- 操作員須年滿 18 歲並經過設備培訓
- 嚴禁单人操作時離開設備運行區域超過 5 分鐘
- 孕婦及佩戴心臟起搏器者應避免靠近电磁干扰源
- 任何改動須經管理人員書面批准

## 5. 標準操作流程

### 5.1 開機流程（正常啟動，約 5-10 分鐘）

```
步驟 1: 硬體開機
  1.1 確認總電源開關位於 OFF
  1.2 連接 12V 適配器（牆壁插座）
  1.3 連接 USB-C 供電給 Pi
  1.4 開啟總電源開關
  1.5 等待 Pi 完成啟動（約 1-2 分鐘，綠燈閃爍後熄滅）

步驟 2: 軟體啟動
  2.1 SSH 進入 Pi 或在本地終端：
      ssh pi@10.0.0.100
  2.2 進入項目目錄：
      cd ~/sorter-project/sorter
  2.3 啟動 MQTT broker（如未運行）：
      sudo systemctl start mosquitto
  2.4 啟動儀表盤：
      python3 control/dashboard.py
      （或 python3 -m control.main 使用 CLI）

步驟 3: 系統初始化（約 2-3 分鐘）
  3.1 等待狀態顯示 INITIALIZING → READY
      （包含感測器預熱、相機自動曝光校準）
  3.2 檢查 MQTT 連接狀態顯示 ✅
  3.3 如狀態顯示 FAULT，查看日誌並參考第 8 節故障排除

步驟 4: 預熱與環境補償
  4.1 讓系統運行 5 分鐘（空跑，無豆子）
  4.2 顏色檢測系統完成白平衡自動校準
  4.3 含水率感測器完成基線穩定
  4.4 觀察日誌，確認無錯誤：
      [INFO] 系統預熱完成，各模組就緒
```

### 5.2 正常運行流程

```
步驟 1: 設定批次參數
  1.1 在儀表盤點擊「批次設定」或 CLI 輸入：
      load 2.0
      batch 2026-04-30-A
  1.2 確認批次目標重量顯示正確

步驟 2: 倒入生豆
  2.1 將待分選生豆倒入入料斗
  2.2 建議每次最多 2kg（避免堆積影響尺寸分選）
  2.3 輕輕拍打入料斗側面，幫助豆子自然下落

步驟 3: 啟動分選
  3.1 點擊 [Start] 或 CLI 輸入：start
  3.2 觀察狀態：READY → FEEDING → RUNNING
  3.3 確認給料速度穩定在 45-55 bpm
  3.4 確認顏色/重量/含水率數值正常更新

步驟 4: 監控運行
  4.1 每 5 分鐘檢查一次：
      - 剔除容器是否接近滿（每 500g 更換一次）
      - 合格品容器重量讀數是否正常
      - 故障計數是否異常增加
  4.2 如給料速度低於 40bpm，檢查入料斗是否缺豆
  4.3 如故障燈亮，立即查看日誌

步驟 5: 批次完成
  5.1 當達到目標重量時，系統自動停止（或點擊 [Stop]）
  5.2 記錄批次報告（自動保存至 db/）
  5.3 更換容器，開始新批次
```

### 5.3 正常關機流程（重要！）

```
⚠️ 嚴禁直接拔電源關機！否則可能損壞 HX711 零點飄移、SD 卡數據丟失

步驟 1: 停止進料
  1.1 點擊 [Stop] 或 CLI 輸入：stop
  1.2 等待當前通道內豆子完成處理（約 30 秒）
  1.3 狀態顯示 READY

步驟 2: 軟體關閉
  2.1 在儀表盤點擊 [Reset] 確認系統歸位
  2.2 關閉 dashboard.py 窗口或 CLI 按 Ctrl+C
  2.3 等待狀態完全停止

步驟 3: 硬體關電
  3.1 關閉總電源開關
  3.2 拔除 USB-C（Pi 供電）
  3.3 拔除 12V 適配器（可選，保持供電以維持MQTT監控）

步驟 4: 清理（每日操作後）
  4.1 清空入料斗剩餘豆子
  4.2 用乾燥刷清理尺寸分選孔板
  4.3 清理光電感測器鏡片（乾燥軟布）
  4.4 更換剔除容器（密封處理）
  4.5 記錄今日批次數據
```

## 6. 批次操作指南

### 6.1 批次定義

每批次為一次完整的生豆分選作業，包含：
- 批次名稱（自定義，如：ETH-2026-04-30-A）
- 目標重量
- 實際分選結果
- 每個合格/剔除豆的詳細數據

### 6.2 批次參數建議

| 應用場景 | 目標重量 | 建議給豆量 | 預計耗時 |
|---------|---------|-----------|---------|
| 日常測試 | 0.5 - 1.0 kg | 1.5× 目標 | 15-30 分鐘 |
| 標準批次 | 2.0 kg | 4.0 kg | 60-90 分鐘 |
| 大量處理 | 5.0 kg | 10.0 kg | 2-3 小時 |

### 6.3 批次監控指標

在運行過程中關注以下指標是否偏離正常範圍：

| 指標 | 正常範圍 | 異常信號 |
|------|---------|---------|
| 給料速度 | 45-55 bpm | <40 bpm 或 >60 bpm |
| 顏色分數 | 70-100 分 | <50 分（黑豆/發酵豆比例升高）|
| 單粒重量 | 0.15-0.25g | <0.10g（發育不全/空心豆）或 >0.30g（超大豆）|
| 含水率 | 10-13% | <8%（過乾）或 >15%（過濕）|
| 故障頻率 | <1次/百粒 | >2次/百粒（系統故障預兆）|

### 6.4 批次數據導出

```bash
# 導出所有批次數據
cd ~/sorter-project/sorter
python3 -c "
from db.database import Database
db = Database()
batches = db.get_all_batches()
for b in batches:
    print(f'批次: {b.name}, 重量: {b.total_weight}g, 良品: {b.good_count}, 剔除: {b.reject_count}')
"

# 或通過 REST API
curl http://localhost:5000/api/batches
```

## 7. 維護保養

| 項目 | 方法 | 注意事項 |

| 項目 | 方法 | 標準 |
|------|------|------|
| 3D 列印件檢查 | 目視檢查裂紋/磨損 | 發現裂紋立即更換 |

## 8. 故障排除

### 8.1 故障代碼速查表

| 故障代碼 | 名稱 | 原因 | 解決方法 |
|---------|------|------|---------|
| F001 | I2C設備未找到 | AD7746未連接或地址錯誤 | 檢查I2C接線，運行 `i2cdetect -y 1` |
| F002 | HX711通訊失敗 | GPIO22/27接線錯誤 | 檢查SCK/DAT接線（見WIRING_GUIDE.md）|
| F003 | 馬達初始化失敗 | 馬達驅動器故障 | 檢查12V供電，測量驅動器輸出 |
| F004 | 顏色相機無響應 | USB Camera未識別 | 拔插USB，重新識別 `ls /dev/video*` |
| F005 | MQTT連接失敗 | Broker未運行 | `sudo systemctl restart mosquitto` |
| F006 | 緊急停機觸發 | E-Stop被按下或軟體故障 | 排查原因後按Reset復位 |
| F007 | 給料器堵塞 | 異物或豆子堆積 | 停機清理，檢查孔板是否堵塞 |
| F008 | 批次超重 | 稱重感測器飄移 | 重新校準（見DEBUGGING_GUIDE.md）|
| F009 | 氣噴閥故障 | GPIO輸出異常 | 測量12V線圈電壓 |
| F010 | 記憶體不足 | 圖像緩衝洩漏 | 重啟Pi，檢查 `/tmp` 目錄 |

### 8.2 常見問題快速排查

#### Q1: 系統狀態顯示 FAULT，但不知道原因

```
步驟：
1. 查看儀表盤底部「事件日誌」最新 ERROR 條目
2. 對照故障代碼表（F001-F010）
3. 如無法確定，截圖日誌聯繫技術支持
```

#### Q2: MQTT 連接失敗（狀態顯示 ❌）

sudo systemctl status mosquitto

# 如未運行，啟動

# 測試連接
mosquitto_pub -t test -m "hello" -h localhost

```

```

#### Q4: 稱重讀數不穩定（波動 > ±0.05g）

```
可能原因：
1. 氣流影響（關閉附近門窗/風扇）
2. 振動傳遞（設備放置平穩，加橡膠墊）
3. 溫度漂移（預熱時間不足）
4. HX711 接線鬆動

解決：
1. 等待預熱 10 分鐘
2. 檢查 Load Cell 安裝是否有機械應力
3. 重新固定 GPIO 線
4. 如仍不穩，執行「DEBUGGING_GUIDE.md」中的 HX711 調試章節
```

#### Q5: 給料速度過慢（< 40bpm）

```
可能原因：
1. 入料斗豆量不足
2. 振動給料器參數偏低
3. 豆子含水率高（粘連）

解決：
1. 添加豆子至入料斗 1/2-2/3 高度
2. 調整振動頻率（CLI: `feeder speed 60`）
3. 乾燥過濕豆子（含水率 >15%）
```

#### Q6: 空壓機不啟動

```bash
# 檢查 12V 供電
測量適配器輸出電壓（目標 12V±0.5V）

# 檢查繼電器
測量繼電器線圈電壓（GPIO控制）
echo "1" > /sys/class/gpio/gpio18/value  # 測試GPIO18
測量12V輸出是否導通

# 檢查空壓機本身
直接用12V供電測試（如有獨立電源）
```

## 9. 緊急停機程序

### 9.1 緊急停機觸發條件

立即按下 E-Stop 或輸入 `estop`：
- 任何異響、異味（燒焦味）
- 馬達異常發熱（>60°C）
- 電氣冒煙或火花
- 豆子堵塞導致設備振動異常
- 任何威脅人身安全的情況

### 9.2 緊急停機步驟

```
⚠️ 保持冷靜，按順序執行以下步驟：

1. 【立即】按下 E-Stop 按鈕或 CLI 輸入：estop
2. 【30秒內】關閉總電源開關
3. 【1分鐘內】拔除主要電源適配器
4. 【5分鐘內】檢查機械部分是否有損壞
5. 【10分鐘內】聯繫技術支持（見聯繫方式）
6. 【24小時內】填寫設備事故報告表

⚠️ 緊急停機後嚴禁自行重新啟動設備！
未經授權不得清除故障代碼或強制復位。
```
